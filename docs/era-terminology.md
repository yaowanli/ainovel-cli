# 时代称谓对照表（维护指南）

时代称谓是**静态维护**的资料，不经过模型生成。

## 为什么不用 LLM

知识检索型任务：无推理深度、错一条代价极高，却要付出数分钟思考和一次失败风险。
实测 `reasoning_effort=medium` 下让模型生成东汉称谓表：

| max_tokens | 结果 |
|---|---|
| 8192 | 155s 思考烧光预算 → 输出被截断（`stop_reason=length`，llmcontract 视为不可重试的硬失败） |
| 32768 | 思考 303s → decode 失败 → 重试后仍超时 |

思考 token 与 JSON 输出共享同一预算，所以调大预算只会让它思考更久。静态表零延迟、
零费用、可审阅、可版本管理，且与既有 genre pack 资产体系一致。

## 两个消费点

1. **writer 提示词全程注入**（`novel_context` 的 `era_terminology`）。
   与 `style_reference` 不同：那是写作技巧，只在前 3 章注入；这是词汇表，
   第 200 章照样会写错「相公」，所以全程注入。architect 阶段也注入——
   人名与封号在大纲阶段就该定对。
2. **`/rules era <朝代>`** 解析为待裁决候选，与 `/rules adopt` / `reject` 共用
   同一套裁决流程，区别只在来源标注（`static_table` vs `auto_generated`）。

采纳前逐条确认：一条错的时代词条会被系统当作权威**强制改写正文**。

## 内置表

`assets/references/genres/history/era-terminology.md`，**当前只内置于 history 题材包**。
其他题材（如仙侠）无内置表，留空而非回落到 history——让仙侠拿到汉代称谓表比拿不到更糟；
这类题材请自行提供覆盖文件。

## 本书 / 全局覆盖

内置表无法预置你书里的东西：主角封号、军中互称、虚构门派叫法。写进：

```
output/novel/style/era-terminology.md      # 只对本书生效
~/.ainovel/style/era-terminology.md        # 对你所有书生效
```

三层覆盖：内置 < 全局 < 本书。**无内置表时覆盖仍然生效**（用户给自己题材准备的表
不该因内置缺失被丢弃）。

覆盖文件里可以三种写法：

| 写法 | 含义 |
|---|---|
| `- **相国** → 丞相 / 国相` | 禁用「相国」，替代项为两个 |
| `- **玻璃** → —` | 该时代无对应写法，只禁用、不给替代项 |
| `- **相公** → 相公（可用）` | 正向确认该词在本朝代正确，不生成候选 |

**解封内置禁用项**：在内置禁用之后（覆盖内容总是追加在后面）再写一条
`- **相公** → 相公（可用）`。解析分两遍，第一遍收集所有「可用」声明，第二遍
剔除对应禁用项——顺序不影响结果。写完请用 `/rules era <朝代>` 确认候选里
已经没有那个词；不生效的话写在这里也不会有提示。

## 解析规则

行格式：`- [可选加粗] 禁用词 → 写法1 / 写法2 [| 理由]`

- 替代项里的括注会被剥掉：`拙荆（可用）` → `拙荆`。否则 writer 会照着带括注的字面写。
- 同一禁用词去重，取**首条**；但「可用」声明在去重**之前**投票，所以任何位置都能解封。
- 代码块（```）内的行跳过——防止文档示例被当成真条目。
- **正向确认条目必须跳过**，否则在东汉书里禁用「太守 / 刺史 / 朝廷 / 陛下」是
  灾难性误伤。判定三种形态：替代项等于禁用词本身、替代项写着「可用 / 慎用 /
  不可用」、note 以「可用 / 不可用」开头。

## 加新朝代

在表文件里加一节，用 `- **词** → 写法 [| 理由]` 格式即可，不需要改代码。
理由列是给人看的，写清年代依据便于复核。
